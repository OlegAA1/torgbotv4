# Telegram-уведомления

Версия: `telegram-notify-v1`. Механизм перенесён из `torgbotv3/bot/notifier.py`: токен и номер чата берутся из окружения, отправка идёт из фоновой очереди через Bot API `sendMessage`, любой сбой Telegram только пишется в лог. Логика стратегий, политика пилота и расчёты paper-счёта не менялись.

## Настройка

1. В Telegram создайте бота у `@BotFather` и получите токен.
2. Узнайте номер своего чата у `@userinfobot` (для группы это число с минусом).
3. Один раз напишите своему боту `/start`. Пока вы этого не сделали, Telegram не даёт боту писать вам.
4. На сервере добавьте в `.env.server`:

```
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TELEGRAM_CHAT_ID=номер_чата
```

5. Примените настройки и проверьте связь:

```sh
docker compose up -d --force-recreate
docker compose exec terminal node scripts/telegram_test.mjs
```

Скрипт проверяет токен, отправляет одно тестовое сообщение и при ошибке подсказывает причину. Токен он не печатает. Без запуска Docker: `node --env-file=.env.server scripts/telegram_test.mjs`.

Токен хранится только в `.env.server` на сервере. Файл не попадает в Git (`.env*` в `.gitignore`) и в Docker-образ (allowlist `.dockerignore`). Не вставляйте токен в чаты и код. Если токен всё же попал в чужие руки, выпустите новый командой `/revoke` у `@BotFather`.

Если `TELEGRAM_BOT_TOKEN` или `TELEGRAM_CHAT_ID` пусты или неверного формата, уведомления выключены, остальное работает как раньше. Причина попадает в лог при старте.

## Что приходит

| Тип | Переменная отключения | Сообщения |
| --- | --- | --- |
| Сигналы | `NORTHSTAR_NOTIFY_SIGNALS=0` | Новый прогноз «ГОТОВ» разрешённого пилота: направление, цена, цель, стоп, R:R, веса сценариев. Один раз на закрытую свечу инструмента. |
| Сделки | `NORTHSTAR_NOTIFY_TRADES=0` | Открытие и докупка виртуальной позиции, закрытие (цель, стоп, срок, ручное) с PnL, комиссиями и funding, пропуск входа из-за лимита позиций или группы корреляции. |
| Системные | `NORTHSTAR_NOTIFY_ALERTS=0` | Запуск и остановка сервера, проблемы сканера и их устранение. |

Время в сообщениях показывается в поясе `NORTHSTAR_NOTIFY_TZ_OFFSET_HOURS` (по умолчанию 3, подпись `NORTHSTAR_NOTIFY_TZ_LABEL`, по умолчанию МСК). Журнал и база остаются в UTC.

### Как работает слежение за сканером

Сканер считается неисправным, если два прохода подряд ничего не удалось просканировать, либо перестали отвечать не менее половины инструментов, которые раньше сканировались успешно. Инструменты, которые не работали никогда (снятые с торгов, без истории), в расчёт не входят, поэтому постоянные ошибки по ним шума не создают. Сообщение приходит один раз, затем один раз приходит сообщение «Сканер восстановился».

## Надёжность и ограничения

- Отправка не блокирует сервер, сканирование и учёт сделок: сообщения идут в очередь (до 100), не чаще одного в 1,1 секунды, при ошибке сети повторяются один раз, при лимите Telegram (429) выдерживается пауза `retry_after`.
- Одно событие не отправляется дважды: у открытия, закрытия и пропуска входа есть ключ, сообщение о блокировке уходит только при смене причины, а не на каждом минутном проходе. После перезапуска сервера память о ключах сбрасывается, поэтому блокировку, которая ещё действует, система может объявить повторно один раз.
- Это уведомления, а не мониторинг. Если сервер выключен целиком, сообщения прийти не может. Для оповещения о полной недоступности нужен внешний сервис, например healthchecks.io или UptimeRobot, который опрашивает `/healthz` или принимает «пульс».
- Сообщения о запуске и остановке сервера отправляются на лучших усилиях: при жёстком завершении процесса (kill -9, потеря питания) сообщение об остановке не придёт.
- Telegram может быть недоступен с некоторых серверов или сетей. Проверка — `scripts/telegram_test.mjs`.
- Уведомления относятся только к виртуальному счёту. Реальные ордера терминал не отправляет.

## Проверка

- `tests/telegram-notifier.test.mjs` — 12 тестов: выключение без ключей, формат запроса, отключение типов, очередь и порядок, повтор при сбое сети, ответ 429, токен не попадает в логи, дубли и переполнение очереди, проверка бота, форматы сообщений, слежение за сканером.
- `tests/paper-queue-overlap.test.mjs` — ещё 2 сквозных теста на SQLite в памяти: автовход и закрытие по стопу объявляются по одному разу, блокировка по группе корреляции объявляется один раз за несколько проходов.
- `tests/server-telegram.integration.mjs` — настоящий процесс сервера присылает сообщение о запуске на локальный поддельный Telegram и не пишет токен в вывод. Требует `pnpm build:server`, запускается через `pnpm test:server:integration` (в общий `pnpm test` не входит, как и серверные проверки).
- Под `node --test` общий отправитель игнорирует настоящие ключи из окружения, поэтому тесты не могут отправить реальное сообщение.

## Откат

Очистите `TELEGRAM_BOT_TOKEN` в `.env.server` и пересоздайте контейнер: уведомления выключатся. Данные в базе уведомления не меняют.
